# Proposal

## Why

Kafka and MirrorMaker configuration properties can only be set through `environmentVariables` entries
encoded as `CONF_KAFKA_*` shell identifiers (e.g. `CONF_KAFKA_NUM_IO_THREADS=16` instead of
`num.io.threads=16`). This forces administrators to hand-translate every property name before applying
a change and prevents Apache Kafka and MirrorMaker documentation examples from being used directly,
introducing a persistent source of misconfiguration failures.

## What Changes

- Add `kafka.config` as an optional `map[string]string` field in the Kafka CRD (`netcracker.com/v1`)
  and in the `kafka` Helm chart values/schema. Keys are native Kafka broker property names; values
  are written verbatim to `server.properties`.
- Add `mirrorMaker.config` as an optional `map[string]string` field in the KafkaService CRD
  (`netcracker.com/v7`) and in the `kafka-service` Helm chart values/schema. Keys are native
  MirrorMaker (Kafka Connect / MM2) property names; values are written verbatim to `mm2.properties`.
- Preserve all keys exactly as specified — no prefix stripping, no case conversion, no
  underscore/dot substitution.
- When the same property is set through both `config` and `environmentVariables`, the
  `environmentVariables` value is applied and the `config` value is ignored.
- Keep the existing `environmentVariables` mechanism fully supported and unchanged.
- Run `make generate` and `make manifests` after the CRD field additions.
- Document the new mechanism with examples, backward compatibility, and precedence rules.

## Capabilities

### New Capabilities

- `kafka/native-config`: Kafka broker properties can be specified as a native-name map under
  `kafka.config`; entries appear in `server.properties` under their original names.
- `mirror-maker/native-config`: MirrorMaker properties can be specified as a native-name map under
  `mirrorMaker.config`; entries appear in `mm2.properties` under their original names.

## Impact

- **operator/api/v1/kafka_types.go** — add `Config map[string]string` to the `Kafka` spec struct.
- **operator/api/v7/kafkaservice_types.go** — add `Config map[string]string` to the `MirrorMaker`
  struct.
- **operator/controllers/provider/kafka_provider.go** — apply `Config` entries when building the
  Kafka pod, with `environmentVariables` entries taking precedence.
- **operator/controllers/provider/mirror_maker_provider.go** — apply `Config` entries when building
  the MirrorMaker pod, with `environmentVariables` entries taking precedence.
- **docker-kafka/3/docker-entrypoint.sh** and **docker-kafka/4/docker-entrypoint.sh** — support a
  new injection path that writes native-name entries directly to `server.properties` without name
  transformation.
- **mirror-maker/docker/docker-entrypoint.sh** — support a new injection path that writes
  native-name entries directly to `mm2.properties` without name transformation.
- **operator/charts/helm/kafka/values.yaml** and **values.schema.json** — add `kafka.config` as an
  optional object with `additionalProperties: true`.
- **operator/charts/helm/kafka-service/values.yaml** and **values.schema.json** — add
  `mirrorMaker.config` as an optional object with `additionalProperties: true`.
- **CRD manifests** (`operator/config/crd/bases/`, chart `crds/`) — regenerated by `make manifests`.
- **docs/public/** — new documentation section covering both parameters, examples, and precedence.
